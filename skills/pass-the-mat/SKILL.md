# Pass the mat

Lens edition of `handoff`. `handoff` is the full version.

Use this skill at the end of an ABC chain. Also use it at every honest stop.

## Use

- You stop for now, and the next session does not have this context.
- Part of the task did not run. The note must say that. Do not write "should be fine."
- This session made a correction. If the correction stays only in the chat, the next session must learn it again from the start.

## The move

1. Did this session find something durable and non-obvious? Examples are a method ruling, a constraint that the code does not show, or a mistake that already cost a session. If yes, update the existing memory entry.
   - Do not create a second entry for the same fact.
   - Do not store secrets, task lists, or data that git already records.
2. Write a handoff that is short enough to act on. Include these items:
   - What changed.
   - What was verified, and how. Keep this separate from what was assumed.
   - What is still open. Include each check that did not run.
   - The single next step, and the vessel that it belongs to. A choice goes to `intercept`. A trained move names the matching lens skill.
3. If the way did not hit its falsifier, say that the way is unfinished. Do not change an unfinished attack into a success narrative.

## Do not

- Paste the transcript.
- List every file that you read.
- Call a blocked obstacle a failure. If `whose-move` already named the obstacle, `blocked_by` is a complete handoff.
