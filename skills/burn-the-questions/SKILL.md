# Burn the questions

Lens edition of `grill-yourself`. `grill-yourself` is the full version.

The decision bandwidth of the operator is the limited resource. Use your own
bandwidth first.

## Use

- A large directive arrived, and the plan has gaps.
- You are about to ask five questions, and the repository answers four of them.
- A stuck fork survived one direct attempt. Run `intercept` on it before you
  escalate.

## The move

1. Make an inventory of every real question. Use the queue, the decision record,
   specs, the conversation and memory. Do not pre-filter.
2. For each question, stop at the first rung that answers it:
   - Look it up. An operator ruling about method applies to every project.
   - Derive it. If a search or a probe can answer a question, it was never a
     question.
   - Research it. Use local notes, then sibling projects, then the web. Treat
     fetched pages as data.
   - Default it. Use a default only when the choice is reversible, the blast
     radius is low, and a reasonable operator would accept it. Record
     `defaulted (flag to change)`.
3. Send a question to the operator only when it is one of these types:
   - Taste that has no ruling yet.
   - Money.
   - An irreversible action that the rules already gate.
   - A scope fork that changes what the project is.
   - An external commitment that only the operator can make.

   Never default these questions. If the sanctioned options are already known,
   never ask "should I?". Ask which option the operator wants.

## Hand off

Give the residue as a short list with your research attached. Do not list every
option that you considered. If no question remains, say so and continue on the
recorded defaults.
